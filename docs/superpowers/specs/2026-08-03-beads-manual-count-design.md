# 拨念珠念的那些，怎么记进来

2026-08-03

## 场景

念佛不一定开着 App。**拨念珠是常态，App 反而是辅助。**
一串念珠 108 颗，拨完 3 串是 324 声。他做完功课才打开 App，
要把这 324 声记上。

这不是「顺手做一下」的需求。按本 App 的立身之本——**一声都不能丢，也一声都不能多**——
记这一笔的路要是硌人，用户就会推到晚点记，然后忘掉（**丢**），
或者凭记忆估一个数（**多或丢，且他自己不知道**）。
**一条难走到没人走的路，产出的正是这个 App 存在的理由要防的那种损失。**

## 先核对现状，不凭印象

| 路 | 实际情况 |
|---|---|
| 今日页 →「补记」→ 数量框 → 记上 | ✅ **已经能走通**。念佛是计数类，补记页**不问时分**（时分只在计时类出现）。选日子默认今天 |
| 定课 → 计数器 → **长按** → 批量增加 | ⚠️ 入口是隐藏手势；档位十档最大 1080；**「自定」是 `Stepper`** |
| 记错了想改这一笔的数 | 只能撤销 + 重记 |

初稿曾把「补记页要填时分」列为障碍，**读了代码之后发现是错的**，已改正。

## 三处判定

### 1 ⛔「自定」名不副实 —— 修

```swift
Stepper(value: $step, in: 1...100_000)
```

上限写着十万。拨了 3 串要 324，档位里没有，从 108 调过去**要点 216 下**。
**一个到不了的上限就是在说谎。**

**改成键盘直接输数**，与补记页的数量框同一形状（`TextField` + `.numberPad` +
`Binding<Int>.numericText` + `.accessibilityLabel`）。
`numericText` 的文档注释里记着一次十倍事故（`TextField(value:format:)` 把 0
留在框里，光标落在前面就成了 5000），**这正是不另起炉灶的理由**。

`Stepper` 整个去掉：批量加数时挪动一颗的意义本就不大（档位里有 1），
而一个够不着自己上限的 `Stepper` 比没有更坏。

**顺带堵一个「多」**：`numericText` 把空框映射成 0，而
`CounterViewModel.setBatchStep` 会 `max(1, step)` 把 0 抬成 1。
于是按钮上写着「加 0」、实际加 1——**屏幕说的和做的不是同一件事**。
`step < 1` 时「加」按钮**禁用**。

### 2 ⛔ 批量增加只有隐藏长按 —— 修

计数区现在挂着：

```swift
.accessibilityHint("轻点加一，长按批量增加")
```

**这句话是念给 VoiceOver 用户听的，而读屏模式下长按被系统接管，他做不到。**
说了做不到，比不说更坏——与 §6.3.1「半真的承诺比不承诺更坏」是同一条。

- 控件区（`controls`，**本就不在计数区内**，不缩小可点面积）加一个看得见的
  「加一批」按钮；
- 提示词改成 `"轻点加一"`，不再承诺做不到的事；
- 长按**保留**，它对明眼用户是个好捷径。

### 3 改已记的那笔 —— 不动

「撤销不会删掉原记录，而是补一笔相反的账，来龙去脉都留着」是有意的决定，
是账本的立身之本。**不在一次功能补丁里单方面推翻它。**
真要做「改这一笔」，也应当是「撤销 + 重记」的一层外衣，而不是原地改数。
另立条目。

### 4 按「串」记 —— 不做

拨珠的人心里数的是串（1 串 = 108）。但键盘能打出 324 之后，
再引入一层单位换算，等于给「一声都不能多」**多开一个出错的口子**。
档位里已有 108（一串）、216（两串）、1080（十串）。

## 验收

| 断言 | 手段 |
|---|---|
| 按钮上写的数，就是要加的数 | 单元 |
| 数写不出来（空框 / 0）时不许按 | 单元 |
| 计数器上有个**看得见**的批量入口 | e2e |
| 长按选 500 仍然照旧 | e2e（`08-batch-exact` 已有）|
| 键盘输 324、加进去就是 324 | e2e + 库里取证 |
| 提示词不再承诺长按 | 单元 |

⚠️ e2e 挑的数**不许挑 108**——`defaultBatchStep` 就是 108，
挑它等于没验（`e2e/README.md`「挑档位的测试别挑默认档」）。
